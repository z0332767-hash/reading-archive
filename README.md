# Reading Archive — Phase 4.1（视觉舒适度优化）

一个本地优先的个人阅读档案原型。它不是读书打卡工具，而是将书籍、划线、点评和待整理想法放进同一个可检索档案。

## 当前功能

- 书库：搜索书名、作者、摘要、划线和点评，并按状态、主题筛选。
- 书籍详情：明确区分作者原文、个人点评与整理状态。
- Inbox：一次处理一条未整理笔记，补充理解、类型和标签。
- 导入：JSON 文件或粘贴文本，写入前展示新增与重复记录。
- 去重：按书籍 ID/书名作者及笔记内容哈希去重。
- 导出：完整 JSON 备份与 Markdown 阅读档案。
- 持久化：当前阶段使用浏览器 `localStorage`，刷新或重启本地服务后保留。
- 响应式：桌面端为高信息密度档案界面，手机端切换为顶部导航。
- 微信读书：通过腾讯官方只读 Agent API 同步有笔记的书、阅读进度、划线和个人想法。
- Today：每天选择 3 条已经整理或包含个人想法的内容重新回顾。
- 观点变化：记录仍然认同、开始存疑、已经改变、继续思考或可用于写作，并保留当下补充。
- 读完仪式：已读书籍拥有六问结案页，保存它真正留下的判断、分歧、连接和写作方向。
- 观点与问题：Inbox 中的洞见和问题可以脱离单本书，进入独立的思想档案。
- Knowledge OS 界面：冷白/石墨视觉系统、信号蓝强调色、等宽元数据与更紧凑的信息层级。
- 明暗主题：自动跟随首次系统偏好，并可在左侧切换；选择会保存在当前浏览器。
- Search 2.0：检索书籍、作者原文、我的点评、个人想法、观点、结案页和后续回顾，并可限定搜索范围。
- 档案问答：本地摘要无需 API；可选 OpenAI 综合回答会标注证据强度，并用可点击的 `[S1]` 引用返回原始档案。
- 思想地图：按跨书连接和档案信号整理主题，展示关联主题、涉及书籍与观点演化时间线。
- 显示大小：标准、舒适、大字三档可切换并自动记忆；默认使用更适合拓展屏远距离阅读的“舒适”档。
- 动态卡片层次：保留划线内容的衬线阅读风格，增强卡片留白、悬停反馈、轻量入场动效和键盘焦点。

## 视觉系统

- 界面功能区使用现代无衬线字体，划线原文等阅读内容保留衬线字体，区分“系统”与“文本”。
- 书籍封面取消纸张投影，改为平面色块和细边框。
- 系统状态、日期、计数、章节位置与同步状态使用等宽字体。
- 全局只使用信号蓝表达操作和选中状态，绿色只表示本地保存或连接正常。
- 深色模式不是简单反色，使用独立的石墨表面、边框和文字层级。
- 左侧“显示大小”可以在标准、舒适和大字间循环；正文、元数据和划线原文采用不同幅度放大，避免只做粗暴的整页缩放。
- 划线、Today 回顾、检索来源和观点卡片使用更明确的表面层级与轻微位移反馈，同时支持系统的“减少动态效果”设置。

## 启动

需要 Node.js 20 或更高版本。

```bash
npm start
```

浏览器打开：`http://localhost:4173`

Windows 用户也可以直接双击 `start-reading-archive.bat`，它会启动服务并打开浏览器。

### 从 GitHub 获取

```bash
git clone https://github.com/z0332767-hash/reading-archive.git
cd reading-archive
npm start
```

项目没有运行时第三方依赖；Node.js 负责本地静态服务、微信读书同步和可选的 OpenAI 请求。个人阅读内容保存在浏览器中，不会随着 Git 仓库上传。

## 连接微信读书

1. 启动 Reading Archive，进入左侧“微信读书”。
2. 点击“打开官方授权页面”，或访问 <https://weread.qq.com/r/weread-skills>。
3. 使用微信扫码登录并生成以 `wrk-` 开头的 API Key。
4. 将 Key 粘贴到 Reading Archive，点击“验证并安全保存”。
5. 首次选择“最近 20 本”，点击“读取并预览”；确认数量和书目后再写入。

API Key 只写入本机 `.env.local`，不会进入浏览器存储、导出文件或日志。`.env.local` 已加入 `.gitignore`，本地服务器也明确禁止通过网页访问它。

## Today 与思想档案

- 首页每天提供最多 3 次回顾，七天内刚看过的内容不会重复出现。
- 回顾只选择已经整理、含有个人点评或属于个人想法的内容，避免让未处理划线淹没首页。
- 回顾时选择“存疑”或“已经改变”，对应观点会进入“正在存疑”或“观点已变化”状态。
- 在 Inbox 将内容标记为“一个洞见”会创建观点，标记为“一个问题”会创建待回答问题。
- 观点和问题保留原始书籍与划线来源，可以从思想档案返回书籍详情。
- 已读书籍如果尚未完成结案，会在 Today 右侧出现提醒。
- JSON 备份现在同时包含观点、问题、回顾记录和读完结案页。

## 检索、提问与思想地图

- “检索与提问”默认只在浏览器中运行关键词检索和本地摘要，不需要任何外部服务。
- 搜索范围可以限定为全部档案、只看我的话、作者原文、书籍或观点/问题。
- AI 综合回答是可选项。配置后，单次问题最多发送 12 条命中的来源片段，不会发送整份阅读档案。
- AI 回答使用结构化输出，前端会再次过滤不存在的来源编号；证据不足时必须明确显示“证据有限”或“未找到证据”。
- OpenAI API Key 只保存在本机 `.env.local`，不进入 `localStorage`、JSON 备份或浏览器页面。
- “思想地图”以书籍和笔记中的显式标签为基础，不凭空猜测主题。共同出现在同一本书中的主题会形成连接。
- 主题时间线依次纳入开始阅读、保存原文、个人回应、观点/问题、读完结论和后来回顾；“存疑”或“已经改变”会标为观点修正。

可在页面中展开 AI 配置，也可以手工写入：

```env
OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxx
OPENAI_MODEL=gpt-5.6
```

保存后重启应用。使用 OpenAI Responses API 时请求设置 `store: false`。

### 同步范围与限制

- “有笔记的书”来自官方 `/user/notebooks`，按最近笔记时间分页读取。
- 划线来自 `/book/bookmarklist`，个人想法与点评来自 `/review/list/mine`。
- 微信读书统计中的“笔记数”包含书签；官方接口当前只导出划线和想法，不能导出书签正文。
- 带想法的划线会合并成“作者原文 + 我的点评”，避免生成两条重复内容。
- 同名同作者的手工书籍会与微信读书记录合并，不会重复建书。
- 接口全程只读，不会修改微信读书的书架、划线或点评。

如需换端口：

```bash
PORT=8080 npm start
```

## 导入格式

下载应用内的“导入模板”，或查看 [`sample-import.json`](./sample-import.json)。最小格式：

```json
{
  "books": [
    { "id": "book_001", "title": "书名", "author": "作者", "status": "reading", "tags": [] }
  ],
  "annotations": [
    { "bookId": "book_001", "chapter": "章节", "originalText": "划线原文", "comment": "我的点评" }
  ]
}
```

`status` 可取 `reading`、`finished`、`wishlist`。缺少笔记 ID 时，系统会依据书籍、章节和原文生成稳定标识。

## 数据安全与恢复

- 数据只写入当前浏览器的本地存储，不会上传。
- 每次较大导入前建议先点“导出 JSON”。
- 要恢复备份，在导入页重新选择备份 JSON 即可；重复内容会被跳过。
- “恢复示例数据”会覆盖当前浏览器数据，执行前会再次确认。

## 当前技术边界

这是可验证交互与数据结构的零依赖版本。微信读书同步使用官方 API，但仍由用户主动点击触发；它不是后台实时监听。重复同步会更新书籍进度并跳过已存在的划线和想法。思想地图依赖已有标签，因此标签越稳定，跨书关系越准确。

后续迁移建议：保留当前 `core.mjs` 的导入/去重规则，将存储层替换为 SQLite + Prisma，将页面迁移到 Next.js；随后加入 ImportBatch、回收站、数据库备份和 WeReadImporter 适配器。
